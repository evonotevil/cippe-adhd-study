## Detailed Findings

### [P1] Dark theme: `--ui-warning-ink` inverts role while `--ui-warning` does not

- **Location**: `src/index.css:70-73`; call sites `src/components/ui/StreakFeedback.tsx:13`,
  `src/components/Achievements.tsx:61`, `src/components/RandomSetup.tsx:132`,
  `src/components/PracticeView.tsx:294`, `src/index.css:256` (`.pressable--warning`,
  used by `src/components/Timer.tsx:84`)
- **Category**: Accessibility / Theming
- **Measured**: light **6.35:1**, eye-care **6.35:1**, dark **1.43:1**
- **Cause**: in light and eye-care, `--ui-warning-ink` is a dark ink (L≈0.33) meant to sit
  *on* the amber fill. In dark it becomes a near-white ink (L≈0.93) intended to sit on the
  *app background* — but `--ui-warning` stays light (L≈0.82). Every component that pairs
  `bg-warning` with `text-warning-ink` therefore inverts into near-white on light amber.
- **Impact**: the pomodoro **暂停** button — the only control available while a focus
  session runs — is unreadable in dark mode, and so is the **EXCELLENT!** chip that
  rewards a 3+ answer streak. In an app built around that reward loop, the payoff
  disappears for every dark-mode user.
- **WCAG**: 1.4.3 Contrast (Minimum), AA — fail
- **Recommendation**: split the roles. Keep `--ui-warning-ink` as the on-fill ink and hold
  it dark in all three themes, and introduce a separate `--ui-warning-text` for amber text
  on the app background. Alternatively darken `--ui-warning` in dark theme to roughly
  L≈0.55 so a near-white ink clears 4.5:1 — but check `ProgressBar` and `Celebration`,
  which use `bg-warning` as a pure fill with no ink on top.
- **Suggested command**: `impeccable colorize`

### [P2] Accent text on the app background falls just under AA

- **Location**: `src/components/Settings.tsx` (eyebrow "按你的节奏学习", `text-info`),
  `src/components/Timer.tsx` (eyebrow "专注一下", `text-danger`)
- **Category**: Accessibility
- **Measured**: dark **3.94:1** / **3.95:1**; eye-care **4.13:1** / **4.12:1**; both at
  14px weight 800, which is below the 18.66px large-text threshold, so 4.5:1 applies
- **Impact**: section eyebrows are the first thing that orients a reader arriving on a
  screen; at these ratios they wash out in bright light or on a dimmed phone.
- **WCAG**: 1.4.3 Contrast (Minimum), AA — fail
- **Recommendation**: darken `--ui-info` / `--ui-danger` for eye-care and lighten them for
  dark, or route eyebrow text through a dedicated on-background accent token rather than
  the same value used for solid fills.
- **Suggested command**: `impeccable colorize`

### [P2] Selected option subtitle is dimmed below AA

- **Location**: `src/components/RandomSetup.tsx`, the mode cards ("每题立即看解析")
- **Category**: Accessibility
- **Measured**: **4.00:1** in light and eye-care (12px, weight 600, white at
  `opacity-80` over `--ui-brand-strong`)
- **Impact**: the explanatory line under 学习模式 / 考试模式 is the text that tells a user
  which mode they are picking, and it is dimmest exactly on the card they selected.
- **WCAG**: 1.4.3 Contrast (Minimum), AA — fail
- **Recommendation**: drop `opacity-80` on the selected state and use a solid ink at ~90%
  lightness instead; opacity over a mid-dark fill is what costs the last 0.5.
- **Suggested command**: `impeccable colorize`

### [P3] Global reduced-motion override is broader than it needs to be

- **Location**: `src/index.css:385-399`
- **Category**: Implementation Integrity
- **Impact**: today, none — all seven animated components drive motion through Framer
  Motion with their own `useReducedMotion()` alternatives, and there is not a single CSS
  `@keyframes` in the project, so the blanket `animation-duration: 0.01ms !important`
  currently only collapses `.pressable` press transitions into instant state changes,
  which is correct behavior. The hazard is forward-looking: the `!important` blanket will
  silently kill any future CSS animation, including one that carries meaning.
- **Recommendation**: keep the rule but scope it to `transition-duration` and to the
  properties that actually need taming, so a deliberate reduced-motion animation can still
  be authored later.
- **Suggested command**: `impeccable animate`

### [P3] Repository and docs drift

- **Location**: `README.md` (发布流程), `.gitignore:11`, tracked `dist/`
- **Category**: Implementation Integrity
- **Impact**: the README documents `npm run build` + `git subtree split --prefix dist`,
  but `.github/workflows/deploy.yml` already builds and publishes Pages on every push to
  `main`. Meanwhile `dist` is listed in `.gitignore` yet three stale build artifacts from
  an older commit remain tracked. Anyone following the README would publish that stale
  build; anyone reading `.gitignore` would assume `dist` is untracked.
- **Recommendation**: `git rm -r --cached dist` and rewrite the 部署 section to say that
  pushing to `main` deploys.

## Resolution — same day, `impeccable colorize`

All three contrast findings shared one root cause: **fill colors were doing double duty as
text colors.** A single value cannot clear 4.5:1 against both white ink and a dark
background, so the palette was split by role rather than retuned.

| Token | Role | Change |
| --- | --- | --- |
| `--ui-warning-solid-ink` | new — ink on the solid `--ui-warning` fill | dark in every theme, never overridden |
| `--ui-warning-ink` | unchanged — ink on `warning-soft` and on the page | still flips with the theme |
| `--ui-info-accent` | new — info text on the page background | `0.52` light/eye-care, `0.62` dark |
| `--ui-danger-accent` | new — danger text on the page background | `0.55` light/eye-care, `0.65` dark |

Call sites moved: 5 to `text-warning-solid-ink` (StreakFeedback, Achievements,
RandomSetup step badge, PracticeView flag badge, `.pressable--warning`), 6 to the accent
tokens (Settings, Timer, PracticeView ×2, ResultView, Settings import message).
`opacity-80` → `opacity-90` on the two RandomSetup mode subtitles.

**Verified after the fix, same harness:**

| Check | Before | After |
| --- | ---: | ---: |
| Pomodoro 暂停 button, dark | 1.43:1 | **7.05:1** |
| EXCELLENT streak chip, dark | 1.43:1 | **7.05:1** |
| Settings eyebrow, dark / eye-care | 3.94 / 4.13 | **5.17 / 4.70** |
| Timer eyebrow, dark / eye-care | 3.95 / 4.12 | **5.28 / 4.68** |
| RandomSetup selected subtitle | 4.00:1 | **4.62:1** |
| axe violations, 8 views × 3 themes | 8 | **0** |

No regression: 0px overflow at 320/390/768 × medium/large, zero sub-44px targets, reflow
still 0px at 400% zoom, text scaling unchanged, every focusable element still shows the
3px ring, `oxlint` and `tsc -b` clean.

**Also fixed:** the README documented a `git subtree` deploy that
`.github/workflows/deploy.yml` had already replaced, and `dist/` was gitignored yet
tracked with a stale build. `dist/` is now untracked and the README says what actually
happens.

**Deliberately not changed:** the `prefers-reduced-motion` block. On closer inspection the
project has no CSS `@keyframes` at all and all seven animated components handle
`useReducedMotion()` themselves, so the blanket rule only collapses `.pressable`
transitions into instant state changes — which is the correct reduced-motion behavior.
Changing it would have been churn.
