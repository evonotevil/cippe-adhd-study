# Impeccable Optimize — 2026-09-08

Target: `src/`
Scope: `impeccable optimize` (UI performance only). Accessibility, responsive and
theming findings from the 2026-09-07 audit are untouched here.

## Already fixed since the 2026-09-07 audit

Re-verified against current `src/`, not carried forward:

- Question bank is already a dynamic `import()` (`src/App.tsx`), not in the initial bundle.
- Practice state checkpoints every 15 s plus on `visibilitychange`, not every second.
- The pomodoro timer is deadline-based and no longer wakes on a 250 ms interval.
- Idle timer duration reconciles on settings change.
- `date-fns`, `howler`, `@types/howler` are gone from `package.json`.

## Changes

### Loading

- **`src/motionFeatures.ts` (new), `src/main.tsx`** — `LazyMotion` now loads
  `domAnimation` through a dynamic import. 37 kB minified / 14 kB gzip of motion
  features leaves the critical path and arrives after first paint.
- **`src/App.tsx`** — the question bank is prefetched in `requestIdleCallback`
  (1.2 s `setTimeout` fallback) after mount. Every practice mode needs it, so the
  ~174 kB gzip download now overlaps with reading the home screen instead of
  sitting between the tap and the first question.

### Runtime

- **`src/domain/practice.ts`**
  - `buildLearningStates` no longer copies and sorts on every call. Timestamps are
    ISO-8601 UTC, so lexicographic order is chronological; the array is checked for
    order and only copied/sorted when it actually needs it, which the append-only
    answer log never does.
  - `getTodayStats` walks backwards from the tail and stops at the first attempt
    before local midnight, instead of parsing a `Date` for every answer ever made.
  - `getReinforcementIds` sorts on precomputed timestamp strings rather than
    allocating two `Date` objects per comparison.
  - `createPracticeSession` and `addReinforcementRound` take precomputed
    `learningStates` instead of raw `progress`, so the state is built once per
    change in `useProgress` and reused everywhere.
- **`src/hooks/useTimer.ts`** — persists only when a durable field changes. While a
  phase runs, `timeLeft` is recomputed from `deadline` on load, so the per-second
  tick no longer serializes to localStorage.

### Persistence

- **`src/utils/persistentStorage.ts` (new)** — writes are queued per key, collapsed
  to the newest value, and flushed on idle, on `pagehide`, and on
  `visibilitychange: hidden`. `useLocalStorage` also skips the redundant mount
  write that re-serialized what it had just read.
- **`src/components/Settings.tsx`** — export and import call `flushPendingWrites()`
  before touching localStorage directly, so a queued write can neither be missed by
  a backup nor land on top of imported data.

## Verification

- `tsc -b`, `vite build`, `oxlint`, `impeccable detect --json src` — all clean.
- 80 assertions comparing the rewritten domain functions against the originals over
  0–2 000 answers, 1/3/30-day spreads, sorted and shuffled input; plus session
  composition, key uniqueness, topic scoping and reinforcement ordering.
- Browser pass on both builds: practice flow, answer persistence, reload recovery,
  pomodoro ticking, theme switching. Identical behavior, no console errors.

## Deliberately not done

- **Route-level `React.lazy` for Settings / Achievements / TopicPicker / RandomSetup
  / ResultView** — about 25 kB minified, ~7 kB gzip, in exchange for a network round
  trip on every first tab tap. Wrong trade for an ADHD-focused app where the tap has
  to feel instant.
- **Splitting `explanation` out of the question bank** — 74 kB of the 174 kB gzip,
  but study mode needs it one tap after the question, and idle prefetch already
  hides the download.
- **Compacting the answer log** — history is unbounded by design and feeds the
  export format. Deferred writes remove the pain without changing the data.

## Next

`react-dom` is 174 kB minified, 55% of the remaining initial bundle. It is the floor
for this stack; the next meaningful load win would be a framework change, which is
not worth it here.
